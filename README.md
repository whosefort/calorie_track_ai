# Calories Bot

Telegram-бот, который считает калории и БЖУ по тому, что ты написал текстом (например «съел гречку 200г и куриную грудку 150г»). Умеет вести историю по дням, разбивать на завтрак/обед/ужин, и предупреждать, если в блюде оказалось что-то из твоего личного списка «не ем».

Эта инструкция написана так, будто ты никогда раньше не разворачивал серверные приложения. Если что-то из терминов ниже незнакомо — не пропускай, здесь всё объяснено.

```
Ты в Telegram → бот на сервере (VPS) → модель (Gemini/OpenAI/др.) считает калории
                                     → бот сохраняет историю в свою базу на том же сервере
```

---

## Что нужно подготовить заранее

Перед установкой у тебя должны быть на руках четыре вещи. Собери их все, потом переходи к установке.

### 1. VPS (виртуальный сервер)

VPS — это арендованный компьютер в интернете, который работает 24/7, даже когда твой ноутбук выключен. Именно на нём будет жить бот.

- Нужен **Debian** или **Ubuntu** (самые ходовые дистрибутивы, подойдёт любой хостинг: Timeweb, Selectel, Hetzner, DigitalOcean и т.д.).
- Минимальной конфигурации (1 CPU, 1 ГБ RAM) достаточно с большим запасом.
- **Домен и открытые порты не нужны** — бот сам ходит в Telegram, а не наоборот.
- После заказа хостинг пришлёт тебе: **IP-адрес сервера**, **логин** (обычно `root`) и **пароль** (или SSH-ключ). Это понадобится на шаге подключения.

### 2. Токен Telegram-бота

1. Открой Telegram, найди бота **@BotFather** (это официальный бот Telegram для создания других ботов).
2. Напиши ему `/newbot`.
3. Придумай имя бота (как он будет отображаться, например «Мой Calories Bot»).
4. Придумай username бота — обязательно заканчивается на `bot` (например `my_calories_helper_bot`).
5. BotFather пришлёт токен — длинную строку вида `123456789:AAH...`. Скопируй и сохрани, она понадобится при установке.

### 3. Ключ для LLM (модели, которая считает калории)

По умолчанию используется **Gemini API от Google** — у него есть щедрый бесплатный лимит, этого достаточно для личного использования.

1. Открой [Google AI Studio](https://aistudio.google.com/apikey).
2. Войди с Google-аккаунтом.
3. Нажми **Create API key**.
4. Скопируй ключ — строка вида `AIza...`. Сохрани.

*(Если хочешь другого провайдера — OpenAI, OpenRouter и т.д. — это тоже возможно, см. раздел [«Смена модели»](#смена-модели-опционально) ниже. Для первой установки просто используй Gemini, разберёшься с остальным потом.)*

### 4. Свой Telegram `user_id` (необязательно, но рекомендуется)

Это число, по которому бот поймёт, что писать можешь только ты, а не кто попало.

1. Открой Telegram, найди бота **@userinfobot**.
2. Напиши ему `/start` — он пришлёт в ответ твой `id` (число, например `123456789`).
3. Сохрани это число.

## Установка

### Шаг 1 — подключись к серверу

На Mac и Linux открой приложение **Терминал**. На Windows — **PowerShell** или **Windows Terminal**.

Введи (замени `IP_АДРЕС` на адрес твоего VPS):

```bash
ssh root@IP_АДРЕС
```

Первый раз спросит «подтвердить подключение» — напиши `yes`. Дальше спросит пароль от сервера (тот, что прислал хостинг) — введи его (при вводе пароля символы не отображаются, это нормально, просто печатай и жми Enter).

Если всё получилось — ты увидишь приглашение вида `root@сервер:~#`. Значит, ты внутри сервера, дальше все команды выполняются там.

### Шаг 2 — скачай код бота

```bash
git clone https://github.com/whosefort/calorie_track_ai.git calories-bot
cd calories-bot
chmod +x deploy.sh
```

Если `git clone` пишет «command not found» — сначала выполни `apt update && apt install -y git`, потом повтори команду.

### Шаг 3 — запусти установку

```bash
sudo ./deploy.sh setup
```

Скрипт сам поставит всё необходимое (Python и т.д.) и задаст несколько вопросов. Вот что отвечать:

| Вопрос | Что делать |
|---|---|
| `Вставь Telegram bot token:` | Вставь токен от @BotFather (шаг 2 выше). Текст при вводе не отображается — это нормально, он вводится скрыто. |
| `Режим Telegram: 1) без домена (рекомендуется), 2) webhook с доменом` | Просто нажми **Enter** — оставит режим по умолчанию (без домена, самый простой). |
| `Вставь разрешённые Telegram user_id через запятую или Enter для всех:` | Вставь свой `user_id` (шаг 4 выше). Если хочешь, чтобы бот отвечал вообще всем — просто нажми Enter. |
| `Вставь URL API или Enter для Gemini:` | Просто нажми **Enter** — используется Gemini. |
| `Вставь API key (без Bearer):` | Вставь ключ Gemini (шаг 3 выше). Именно сам ключ, без слова `Bearer`, без кавычек. |
| `Вставь ID модели или Enter для gemini-3.5-flash-lite:` | Просто нажми **Enter**. |
| `Формат ответа: 1) auto — совместимый и рекомендуемый, 2) strict` | Просто нажми **Enter**. |

После этого скрипт сам:
- проверит, что токен и ключ рабочие;
- поставит и запустит бота как системный сервис (он будет работать в фоне, даже после того как ты закроешь терминал и выключишь свой компьютер);
- покажет статус в конце.

Если в самом конце видишь зелёные `[✓]` и строку `Готово. Логи: journalctl -u calories-bot -f` — всё получилось.

### Шаг 4 — проверь, что бот отвечает

Открой Telegram, найди своего бота по username (тот, что придумал у BotFather) и напиши `/start`.

Должно прийти приветствие с кнопками внизу экрана. Если пришло — бот работает, установка завершена. 🎉

Если ничего не пришло — смотри раздел [«Если что-то не работает»](#если-что-то-не-работает) ниже.

## Как пользоваться ботом

Просто пиши, что съел, обычным текстом:

> съел гречку 200г и куриную грудку 150г

Бот посчитает калории и БЖУ.

Внизу экрана в Telegram есть кнопки:

| Кнопка | Что делает |
|---|---|
| ➕ **Добавить** | Записать один приём пищи (завтрак/обед/ужин/перекус) отдельно |
| 📝 **Весь день** | Записать всё съеденное за день одним сообщением |
| 📊 **Сегодня** | Показать сводку калорий за сегодня |
| 📋 **История** | Показать последние записи по дням |
| ✏️ **Переписать** | Исправить/переписать рацион за выбранный день |
| 🚫 **Не ем** | Задать список продуктов, которые ты не ешь — бот будет предупреждать, если они попадут в блюдо |

Если бот ждёт от тебя ввод (например после «Добавить»), а ты передумал — напиши `/cancel`.

## Как обновить бота (когда вышли новые исправления)

Каждый раз, когда в коде что-то поменялось (например, вышел фикс бага), обнови так:

```bash
cd calories-bot
git pull
sudo ./deploy.sh deploy
```

Это скачает новый код и перезапустит бота. **Твои данные (история, настройки) и токены при этом не трогаются** — они хранятся отдельно от кода.

## Если что-то не работает

Все команды ниже выполняются на сервере (из терминала, после `ssh root@IP_АДРЕС`), из папки с ботом (`cd calories-bot`, если ты туда ещё не зашёл).

```bash
sudo ./deploy.sh status     # Работает ли бот прямо сейчас
sudo ./deploy.sh logs       # Живые логи — что бот делает и на чём спотыкается (Ctrl+C — выйти)
sudo ./deploy.sh restart    # Просто перезапустить, если что-то подвисло
```

Частые случаи:

- **Бот вообще не отвечает на `/start`.** Запусти `sudo ./deploy.sh status` — если там написано `active (running)`, но бот всё равно молчит, скорее всего неверный токен или у тебя стоит ограничение по `user_id`, под которое твой аккаунт не подходит. Проверь конфиг: `sudo cat /etc/calories-bot/calories-bot.env`.
- **`sudo ./deploy.sh setup` ругается на что-то и останавливается.** Прочитай последнюю красную строку — там обычно написано, что именно не так (неверный токен, пустой ключ и т.д.). Просто запусти `sudo ./deploy.sh setup` заново.
- **Бот отвечал, а потом резко перестал.** `sudo ./deploy.sh logs` и посмотри последние строки прямо в момент, когда писал боту — там будет видно ошибку.
- **Ничего не помогло.** `sudo ./deploy.sh restart`, подожди 10 секунд, попробуй снова.

## Данные и резервные копии

Всё, что бот запоминает (история еды, твой список «не ем», настройки), и все токены/ключи хранятся **отдельно от кода бота** — вот здесь:

| Что | Где |
|---|---|
| Твоя история и настройки | `/var/lib/calories-bot/calories.sqlite3` |
| Токены и ключи (только root может прочитать) | `/etc/calories-bot/calories-bot.env` |

`git pull` и обновления эти файлы не трогают.

Сделать резервную копию базы вручную (бот продолжит работать во время бэкапа):

```bash
sudo install -d -m 700 /root/calories-backups
sudo sqlite3 /var/lib/calories-bot/calories.sqlite3 ".backup '/root/calories-backups/calories-$(date +%F).sqlite3'"
```

(`deploy.sh deploy` и так делает бэкап автоматически перед каждым обновлением.)

## Смена модели (опционально)

Бот работает с любым сервисом, совместимым с OpenAI Chat Completions API — это не только OpenAI, но и OpenRouter, Ollama, vLLM и другие.

Чтобы сменить провайдера, отредактируй конфиг и обнови бота:

```bash
sudoedit /etc/calories-bot/calories-bot.env
sudo ./deploy.sh deploy
```

Формат файла — `ИМЯ=значение`, без кавычек, без `export`, без `Bearer`.

### Готовые примеры (вставь эти 4 строки вместо текущих `LLM_*`)

**OpenRouter** — ключ начинается с `sk-or-`. [Документация](https://openrouter.ai/docs/quickstart)

```env
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=sk-or-v1_ВСТАВЬ_СВОЙ_КЛЮЧ
LLM_MODEL=~openai/gpt-latest
LLM_STRUCTURED_OUTPUT=auto
```

**Gemini напрямую** (это же стоит по умолчанию после `setup`):

```env
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_API_KEY=AIza_ВСТАВЬ_СВОЙ_КЛЮЧ
LLM_MODEL=gemini-3.5-flash-lite
LLM_STRUCTURED_OUTPUT=auto
```

`LLM_STRUCTURED_OUTPUT=auto` — рекомендуемый режим: бот сначала просит модель вернуть строгий JSON по схеме, а если конкретный провайдер это не поддерживает — автоматически переходит на обычный JSON-запрос. Сервер в обоих случаях сам ещё раз строго всё перепроверяет (см. ниже), так что смена этого параметра не снижает надёжность.

Полный список переменных с комментариями — в файле `config.example.env`.

## Как бот защищается от кривого ответа модели

Модели иногда ошибаются или возвращают не то, что просили. Бот с этим борется на двух уровнях:

1. **Просит у модели строго определённый формат** (JSON Schema) — большинство современных провайдеров это поддерживают и следуют ему.
2. **Сам ещё раз всё перепроверяет** перед сохранением: сходится ли сумма калорий по позициям, не превышает ли белок/жир/углеводы вес самого продукта, не слишком ли много текста, реалистичен ли вес порции и т.д. Если что-то не сходится — бот один раз переспрашивает модель с более строгой инструкцией; если и это не помогло — сообщает тебе об ошибке, а не сохраняет мусор в историю.

Это ловит ошибки формата, но не заменяет реальную базу данных о продуктах — для точного бренда или ресторанного блюда лучше писать вес и марку прямо в сообщении.
